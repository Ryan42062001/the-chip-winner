# TCW-003 — ESPN Field-Validation Feasibility Research

ROLE ROUTING: Research & Development
STATUS: AUTHORIZED AFTER TCW-001 CLOSEOUT MERGES

## TASK ID

TCW-003

## OBJECTIVE

Research current authoritative ESPN Fantasy Football behavior and practical, privacy-safe ways to exercise the remaining ESPN-heavy Release 1.0 field checks without manufacturing states, weakening fail-closed rules, or changing production behavior.

## WHY IT MATTERS

Several Release 1.0 blockers require real authenticated states that may depend on league configuration, injury status, game timing, or controlled failure conditions. Manager needs evidence on which checks can be exercised now, which require a different league/state, and which are inherently seasonal or opportunity-dependent.

## VERIFIED STARTING STATE

Refresh from repository before acting. Expected pending ESPN-heavy checks after TCW-001 closeout include:

- FV-ESPN-02 — authenticated custom FLEX/OP league;
- FV-ESPN-04 — authenticated IR edge states;
- FV-ESPN-05 — authenticated lock/availability transitions;
- FV-SEASON-01 — real playoff and bye intelligence states;
- FV-RECOVERY-01 — live ESPN/session/network failure and reconnect;
- FV-WAIVER-01 — real waiver candidate volume/timing, where ESPN state affects candidate scale.

Do not assume statuses are unchanged; verify `config/field-validation.json` first.

## REQUIRED BEHAVIOR

- Use current authoritative external evidence for ESPN rules/behavior where relevant.
- For each applicable pending check, state the real-world preconditions required to exercise it.
- Distinguish what can be deliberately and safely exercised from what must wait for a naturally occurring league/player state.
- Identify any check that requires access to a materially different league configuration (for example OP/superflex/custom FLEX).
- Identify privacy-safe evidence that would satisfy the existing repository evidence policy without storing credentials, cookies, raw private snapshots, member data, or private sync links.
- Identify likely observation windows (for example before/after kickoff) when timing matters.
- Separate documented ESPN policy from observed/undocumented behavior and from project assumptions.
- Report any API/shape uncertainty that could justify a future sanitized fixture or Builder task, but do not authorize implementation.

## NON-GOALS

- No production code changes.
- Do not mark field checks passed.
- Do not weaken IR, lock, acquisition, identity, missing-data, or source-separation rules merely to make a field state easier to exercise.
- Do not propose ESPN write actions.
- Do not convert research recommendations into product requirements; Manager must evaluate them first.

## EDGE CASES

- If official ESPN documentation is silent or contradictory, say so explicitly and classify the behavior as requiring observation rather than inference.
- If a check cannot currently be exercised without fabricating state, classify it as opportunity-dependent and recommend the safest observation trigger.
- If a practical test would risk mutating league state, prefer a read-only observation path and flag the limitation.

## TEST REQUIREMENTS

No repository tests are required. Research claims must be source-backed where externally verifiable. If a concrete provider shape or deterministic defect is discovered, recommend a sanitized regression fixture/test but do not implement it without Manager authorization.

## REQUIRED VALIDATION LEVEL

Authoritative-source research plus repository-context analysis. No claim of live validation unless actually observed and evidence is available.

## ACCEPTANCE CRITERIA

- Every applicable pending ESPN-heavy field check has a feasibility classification: exercise-now, requires-different-league/state, seasonal/opportunity-dependent, or currently unverified.
- Required preconditions and privacy-safe evidence are identified.
- Officially documented facts are separated from observations and assumptions.
- Any architecture/product implications are presented as recommendations, not decisions.
- No production behavior is changed.
