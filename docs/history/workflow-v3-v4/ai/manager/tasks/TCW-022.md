## OBJECTIVE

Define the production-ready decision contract for **Trade Analyzer v1** before Builder implementation.

The analyzer should answer:

> What happens to my fantasy team if I make this proposed trade, and why?

The policy must evaluate roster consequences instead of producing an opaque single trade-value score.

## APPROVED V1 PRODUCT BOUNDARY

- User-entered proposed trades.
- Analyze the connected user's ESPN team.
- Support one-for-one and multi-player / unequal-count packages on both sides.
- Remain completely read-only: no proposing, sending, accepting, rejecting, or otherwise executing ESPN trades.
- Reuse approved connected-league facts and existing projection/recommendation infrastructure where valid.
- Do not require a new external data source merely to make v1 exist.
- If a required data/feasibility question cannot be resolved from existing approved inputs, return it to Manager as an explicit R&D dependency instead of inventing a heuristic fact.

## REQUIRED STRATEGY CONTRACT

Define how v1 should evaluate and present, at minimum:

1. **Immediate starting-lineup impact**
   - compare the best legal lineup before versus after the proposed trade;
   - identify which starters/FLEX spots change and the supported projected impact;
   - distinguish a real lineup upgrade from value that remains on the bench.

2. **Depth and replaceability**
   - quantify/describe positional depth lost or gained;
   - define replacement-level context using the connected ESPN player pool when available;
   - explain fragility created by concentrating value into fewer players or by losing a scarce backup.

3. **Unequal-count package effects**
   - handle 2-for-1, 1-for-2, 3-for-2, etc.;
   - identify open-roster-slot creation or roster-space pressure;
   - when receiving extra players would require a subsequent drop or other roster action, make that consequence explicit rather than silently assuming a legal final roster.

4. **Time horizons**
   - immediate/current-week impact;
   - selected multiweek/rest-of-season impact only when compatible coverage exists;
   - future/playoff-window analysis only when the underlying data is actually available and sufficiently complete.

5. **Bye-week and playoff effects**
   - identify meaningful bye clustering or relief when supported;
   - identify fantasy-playoff-window effects when supported;
   - withhold unsupported conclusions rather than filling missing weeks with fabricated values.

6. **Projection/source disagreement**
   - preserve source separation;
   - define how disagreement changes the wording/confidence of the conclusion;
   - do not average incompatible sources into a false truth score without an approved policy.

7. **Uncertainty and incomplete evidence**
   - define what can still be concluded when current-week data is complete but future coverage is partial;
   - distinguish projected advantage from confidence in the recommendation;
   - avoid false precision.

8. **Roster legality / known constraints**
   - use known ESPN roster slots, position limits, IR state, and other verified constraints where applicable;
   - do not claim trade-processing legality for ESPN rules/state the product does not actually know.

9. **Recommendation/conclusion taxonomy**
   Define a small, inspectable set of conclusions such as:
   - improves immediate lineup but weakens depth;
   - improves both starters and depth;
   - improves long-term outlook at a short-term cost;
   - creates unacceptable positional fragility;
   - roughly balanced / preference depends on team objective;
   - insufficient evidence for a responsible recommendation.

   Exact labels are Strategy-owned. Do **not** use a single opaque `you win 78-64` style score as the primary conclusion.

10. **Team objective framing**
   - define when a strong/deep team may rationally consolidate into elite starters;
   - define when a fragile/injury-hit team should prefer weekly stability/depth;
   - keep subjective strategy visibly separate from source facts and mathematical projection deltas.

## REQUIRED SCENARIOS

The Strategy artifact must include concrete expected behavior for at least these scenarios:

- 1-for-1 where the incoming player is a clear starter upgrade.
- 2-for-1 consolidation that improves the starting lineup but materially reduces depth.
- 1-for-2 diversification that adds useful depth but may require roster-space handling.
- Trade with little current-week change but meaningful bye-week effect.
- Trade with favorable playoff-window evidence when complete data exists.
- Same trade when playoff/future data is incomplete; recommendation must become appropriately bounded.
- Trade where approved projection sources materially disagree.
- Trade where the nominally higher projected player does not improve the legal starting lineup.
- Trade that leaves one position dangerously thin relative to ESPN free-agent replacement context.
