## REQUIRED AUDIT DIMENSIONS

Audit at minimum:

1. **Read-only / mutation boundary**
   - no ESPN propose/send/accept/reject/veto mutation path;
   - no transaction side effect hidden in analysis/UI;
   - no hidden `tradeScore`, winner percentage, confidence percentage, acceptance probability, or equivalent opaque composite verdict.

2. **Proposal and roster legality**
   - outgoing membership and incoming snapshot identity validation;
   - multi-player / unequal-count proposals;
   - duplicate/conflicting identity rejection;
   - direct versus resolved post-trade roster behavior;
   - no inherited opponent lineup slot;
   - no automatic IR placement;
   - known active-roster size and finite position-limit enforcement;
   - `ROSTER_ACTION_REQUIRED` until explicit required follow-up removals resolve known constraints;
   - no silent drop or free-agent add.

3. **Best legal lineup consequence**
   - pre/post optimizer uses configured starter-slot skeleton correctly for unequal-count hypothetical rosters;
   - no regression to existing lineup-optimizer callers that do not pass the optional configured slot contract;
   - actual starter/FLEX assignment changes are exposed;
   - higher projected incoming bench players do not receive false immediate starter credit;
   - current-week numeric materiality remains +/-1.0.

4. **Lock / actionability semantics**
   - existing explicit ESPN lock and passed-kickoff semantics are reused;
   - locked current-week trade consequences remain informational/counterfactual;
   - UI does not claim ESPN would process a trade involving a locked player.

5. **Depth / replacement / fragility**
   - listed-position depth and legal contingency remain separate;
   - `COVERED`, `THIN`, `SCARCE_THIN`, and narrow `DANGEROUS` behavior matches accepted policy;
   - ordinary depth loss is not automatically `DANGEROUS`;
   - missing ESPN availability remains unknown rather than weak/empty;
   - replacement context is latest-snapshot only and does not become an automatic acquisition.

6. **Bye / future / playoff horizons**
   - unknown bye facts remain bounded;
   - future/playoff numerical conclusions require compatible complete pre/post union-roster coverage;
   - missing weeks are not zero-filled;
   - incomplete windows keep aggregate/mean/direction unavailable/`UNKNOWN`;
   - complete windows expose raw aggregate plus mean weekly delta;
   - materiality uses mean weekly delta at +/-1.0 projected point per evaluated week;
   - large aggregate alone cannot manufacture materiality;
   - partial windows are not mislabeled `REST_OF_SEASON`.

7. **Projection-source separation**
   - compatible sources are evaluated independently;
   - source values are never averaged;
   - accepted material disagreement rules are respected, including material-vs-tossup disagreement;
   - `UNKNOWN` is not converted into agreement/disagreement;
   - source/capture/freshness evidence remains inspectable.

8. **Conclusion precedence / objective framing**
   - narrow `DANGEROUS_POSITIONAL_FRAGILITY` guard remains dominant;
   - `SHORT_TERM_GAIN_LONG_TERM_COST` and `LONG_TERM_GAIN_SHORT_TERM_COST` outrank generic upgrade/depth labels;
   - `CLEAR_TEAM_UPGRADE` and `STARTER_UPGRADE_DEPTH_COST` cannot swallow a supported opposing horizon cost;
   - incomplete future evidence cannot fabricate a conflict;
   - team objective changes narrative framing only, not source facts, thresholds, legality, or numeric conclusions.

9. **UI / browser / accessibility / responsiveness**
   - user can add/remove multiple outgoing and incoming players;
   - objective selection works;
   - explicit follow-up drop workflow is understandable when required;
   - proposal controls and results are clearly separated;
   - roster-space, source disagreement, incomplete evidence, lock state, limitations, and read-only status are understandable;
   - perform reasonable responsive/accessibility sanity review consistent with repository audit evidence.

10. **Regression and evidence quality**
    - inspect focused tests for meaningful assertions rather than tautological coverage;
    - verify exact deployed master CI/deploy/production evidence;
    - identify any material untested edge implied by the accepted contract;
    - do not treat deterministic/sample tests as proof of unobserved authenticated ESPN behavior.
