## OBJECTIVE

Remediate accepted finding `TCW-018-F01 — MEDIUM — BLOCKING` without broadening Release 1.0 scope:

A roster player who is already locked by ESPN or by passed kickoff must not participate in an unqualified actionable START / SIT preference that implies a now-impossible lineup move.

## ACCEPTED IMPLEMENTATION

Builder PR #95 implemented the bounded remediation in:
- `src/ui/start-sit-comparison.js`;
- `test/start-sit-comparison-ui.test.js`;
- `.ai/builder/HANDOFF.md`.

The implementation:
- reuses the complete-lineup optimizer's existing exported `getLineupLockReason()` semantics;
- checks selected roster entries for explicit ESPN lock and checks reported kickoff passage;
- changes locked comparisons to `LINEUP MOVE LOCKED · INFORMATION ONLY` / `NO LINEUP ACTION` rather than an actionable `PROJECTION LEAN`;
- retains projection values as informational context;
- keeps external projections source-separated and changes locked external wording to informational-only language;
- preserves ordinary unlocked preference/tossup behavior;
- preserves missing/invalid comparison behavior;
- does not modify recommendation thresholds, optimizer logic, waiver/acquisition logic, rankings, projections, normalization, IR policy, season intelligence, read-only behavior, or `config/field-validation.json`.

## DETERMINISTIC COVERAGE

Focused regression coverage verifies:
1. explicit ESPN roster lock -> non-actionable START / SIT output;
2. passed kickoff without explicit lock flag -> non-actionable START / SIT output;
3. lock qualification is dominant and visible;
4. external source separation remains intact without action-like locked wording;
5. unlocked preference remains unchanged;
6. unlocked tossup remains unchanged;
7. invalid/missing states remain unchanged;
8. existing complete-lineup optimizer lock tests remain green through the full suite.
