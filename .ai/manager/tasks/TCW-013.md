## Objective
Reduce control-plane churn without weakening validation and make the Manager merge boundary explicit/machine-visible.

## Approved scope
1. Keep the full test/CI gate for every pull request and every `master` push.
2. Skip Pages deploy and production smoke only for `master` pushes whose changed paths are entirely under `.ai/**`.
3. Fail open to deployment whenever changed-path classification is unavailable or ambiguous; manual workflow dispatch always deploys.
4. Keep durable roadmap/decision files free of volatile active-task inventory; `ACTIVE_TASKS.json` remains operational authority.
5. Require active registry tasks to declare `merge_authority: "Manager"`.
6. Explicitly prohibit Builder, Auditor, Strategy, R&D, and Troubleshooting workers from invoking merge/auto-merge. They stop at a validated PR/handoff. An externally merged worker PR is not considered Manager-accepted until Manager independently refreshes, reviews the merged diff/evidence, verifies master, and reconciles canonical state.

## Acceptance criteria
- deterministic deployment-scope tests cover `.ai/**`-only, mixed/product, unavailable, manual-dispatch, and PR cases;
- deploy/verify-production are gated, while test remains unconditional;
- workflow audit rejects active tasks without Manager merge authority;
- Workflow V3.1 documents durable/volatile state, control-plane deployment scope, and merge-authority/provenance rules;
- exact-head CI passes;
- this workflow-changing integration deploys normally because it touches paths outside `.ai/**`;
- a subsequent `.ai/**`-only TCW-013 closeout demonstrates test PASS with deploy/verify-production skipped as NOT APPLICABLE.

## Protected boundaries
No product behavior, field-validation status, recommendation logic, ESPN/provider behavior, or Release 1.0 feature scope changes.
