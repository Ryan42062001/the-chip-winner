## Objective

Reduce workflow churn without weakening validation by:

1. keeping the full test gate for every PR/push while skipping GitHub Pages deploy + production smoke for `master` commits whose changed files are entirely under `.ai/**`;
2. treating deployment/production verification as `NOT APPLICABLE` for those control-plane-only commits;
3. removing volatile active-task inventory from the durable roadmap so `.ai/shared/ACTIVE_TASKS.json` remains the only operational task source of truth.

## Constraints

- Do not touch TCW-012 product/UI/test files.
- Do not change product behavior, recommendation policy, field status, or Release 1.0 scope.
- Fail safe: if deployment scope cannot be classified on a push, deploy rather than skip.
- `workflow_dispatch` must still force a deployment.
- Pull requests continue to run validation without deploying.
- Any `master` commit touching at least one path outside `.ai/**` must continue through Pages deploy and production smoke.

## Acceptance criteria

- deterministic tests cover `.ai/**`-only, mixed/product, empty, and ordinary path classification;
- workflow uses the classifier to gate only `deploy`/`verify-production`, not the test job;
- Workflow V3.1 documents the control-plane deployment rule and durable/volatile state boundary;
- ROADMAP no longer claims a volatile current task list;
- exact-head CI passes;
- Manager merges only after CI and verifies post-merge behavior.
