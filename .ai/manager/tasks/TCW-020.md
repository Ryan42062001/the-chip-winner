## OBJECTIVE

Remediate TCW-018-F01 without broadening Release 1.0 scope:

A roster player who is already locked by ESPN or by passed kickoff must not participate in an unqualified actionable START / SIT preference that implies a now-impossible lineup move.

The complete-lineup optimizer already respects locks correctly. The defect is bounded to the separate generic START / SIT comparison surface.

## REQUIRED BEHAVIOR

When either selected roster player is locked because ESPN reports a lock or because kickoff has passed:

- the START / SIT surface must not render an unqualified actionable preference that implies the locked player can still be moved;
- the UI must make the affected comparison non-actionable or clearly qualified as informational;
- if projection values or external-source comparison context remain visible, the lock limitation must be explicit and must dominate the action guidance;
- source separation must remain intact;
- unlocked START / SIT comparison behavior must remain unchanged.

Acceptable bounded approaches include:
- withholding the preference and returning a locked/non-actionable comparison state;
- rendering the projection comparison as informational only with explicit lock qualification;
- another equally narrow behavior that prevents a locked-player comparison from appearing actionable.

Do not merely hide the complete-lineup optimizer warning or rely on ESPN itself to reject the impossible move.
