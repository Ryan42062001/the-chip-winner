# TCW-005 — FV-RECOVERY-01 Live Failure/Reconnect Validation

ROLE ROUTING: Independent Auditor / QA
STATUS: AUTHORIZED AFTER TCW-004 MERGES AND IS PRODUCTION-VERIFIED

## TASK ID

TCW-005

## OBJECTIVE

Execute one real deployed authenticated ESPN refresh failure/reconnect cycle using a temporary client network disconnect, independently assess whether the last valid snapshot remains usable with honest source/freshness labeling, and verify successful recovery after connectivity returns.

## WHY IT MATTERS

FV-RECOVERY-01 is a Release 1.0 blocker that can be exercised immediately without changing ESPN league state. Repository inspection shows the failed-refresh path preserves the previous valid `live-companion` snapshot while normal UI hydration still labels such a snapshot `Live ESPN snapshot`. A real field run is required to determine whether the deployed behavior actually satisfies or fails the field acceptance requirement.

Refresh repository before acting. Expected state after TCW-004:

- package version: v0.9.88 unless a newer verified checkpoint exists;

  - failed refresh does not replace the existing valid snapshot;
  - `hydrateControls()` labels a `live-companion` snapshot `Live ESPN snapshot`;
  - the refresh failure catch path shows an error notice but does not explicitly transition the stored snapshot into a stale/offline source state.

Do not assume these observations produce a field failure until the deployed workflow is actually exercised.

## REQUIRED BEHAVIOR

Use a real deployed app/browser session and a real authenticated ESPN connection.

1. Start online with the Chrome companion available and complete a successful **Refresh ESPN**.
2. Record privacy-safe environment facts: date/time, OS, browser version, app/deployed checkpoint if visible/known, and the current source/capture/freshness labels without recording league/team/member identity.
3. Keep the loaded page open and temporarily disable the client device's network connectivity at the OS/device level. Do not sign out of ESPN or mutate league state for this first test.
4. Invoke **Refresh ESPN** after any existing application cooldown permits it.
5. Record the actual failure message/class and whether the last valid snapshot remains usable.
6. Record the exact source/freshness labeling shown after the failed refresh. The key acceptance question is whether retained old data is honestly distinguished from a newly refreshed/live state.
7. Verify normal navigation/inspection remains safe and does not fall back to sample data or invent new ESPN state.
8. Restore network connectivity.
9. Invoke **Refresh ESPN** again after any cooldown permits it and verify successful reconnect/refresh.
10. Produce an independent Auditor verdict for FV-RECOVERY-01 evidence:
    - `PASS CANDIDATE` if retention, honest stale/offline/error labeling, and reconnect behavior satisfy the field requirement;
    - `FAIL — REPRODUCED DEFECT` if retained data is materially mislabeled as current/live or another deterministic recovery defect is observed;
    - `INCONCLUSIVE/BLOCKED` if the real test cannot establish the acceptance criteria.

TCW-005 does not directly edit `config/field-validation.json`. Manager owns any subsequent field-status integration after reviewing the handoff.

## EDGE CASES

- Refresh cooldown may require waiting until the control is legitimately available; do not bypass application safeguards.
- Browser or operating-system offline behavior may surface a companion/network error differently than expected; record the actual sanitized failure class.
- If disabling network causes the page itself to reload/unload, repeat using a method that leaves the already-loaded page open if practical.
- If the companion becomes unavailable for reasons unrelated to the network toggle, classify the observation accurately rather than forcing a conclusion.
- If the retained snapshot source label says `Live ESPN snapshot` but a separate visible freshness/error indicator clearly and unambiguously communicates that the data is stale/not refreshed, Auditor must assess the entire user-visible state against the field requirement rather than judging one string in isolation.
