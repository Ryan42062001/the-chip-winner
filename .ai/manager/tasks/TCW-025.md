## ACCEPTED FINDINGS TO REMEDIATE

### TCW-024-F01 — HIGH — replacement-path verification can falsely produce `DANGEROUS_POSITIONAL_FRAGILITY`

Current defect:
- bye coverage exposes uncovered slot candidates as slot-label strings such as `RB`, `FLEX`, and `OP`;
- the Trade Analyzer wraps those labels as objects before passing them through the replacement eligibility helper;
- `canFillSlot()` expects a slot string, so a genuinely eligible replacement can be rejected;
- replacement legality/fragility evaluation also reuses the top-12 presentation shortlist instead of the full relevant latest ESPN availability pool.

Required remediation:
- evaluate replacement eligibility using the actual slot-label contract expected by `canFillSlot()`;
- separate presentation truncation from legality/fragility evaluation;
- use the full relevant latest ESPN availability pool for the DANGEROUS replacement-path determination;
- continue respecting known acquisition/roster constraints;
- keep any replacement acquisition explicitly conditional and separate from the trade itself;
- do not auto-add a replacement.

Required deterministic coverage:
- a known post-trade RB bye gap with an eligible ESPN RB replacement does **not** become DANGEROUS;
- FLEX-compatible and OP-compatible eligible replacement paths are handled correctly where supported by the existing slot model;
- an eligible replacement outside the first 12 presentation candidates is still considered for the structural DANGEROUS check;
- DANGEROUS remains when the latest ESPN pool truly has no verified eligible path;
- DANGEROUS remains when a known acquisition/roster constraint blocks the otherwise eligible path.

### TCW-024-F02 — HIGH — current explicit lock flags leak into future/playoff optimization

Current defect:
- future evaluation time `0` prevents kickoff-time locking from carrying forward;
- explicit current `entry.locked === true` and/or `player.locked === true` still reach the future optimizer;
- this can exclude a player from a future lineup and fabricate a future/playoff delta or cross-horizon conclusion.

Required remediation:
- future/playoff optimization must ignore current-week lock state entirely, including explicit entry/player lock flags and current kickoff-derived locks;
- current-week optimization and current-week informational lock qualification must remain unchanged;
- do not mutate the source snapshot to accomplish this;
- preserve all existing complete-coverage, source-separation, and horizon-materiality rules.

Required deterministic coverage:
- a currently explicit-locked player remains constrained in current-week analysis;
- the same player's explicit entry lock does not constrain a future week;
- an explicit player-level lock does not constrain a future week;
- future/playoff lineup totals and assignments match the unlocked hypothetical future state;
- current lock state cannot fabricate `LONG_TERM_GAIN_SHORT_TERM_COST`, `SHORT_TERM_GAIN_LONG_TERM_COST`, or another horizon conclusion.

### TCW-024-F03 — MEDIUM — unverified contingency coverage is asserted as `THIN`

Current defect:
- when contingency coverage cannot be verified, the analyzer returns `THIN` rather than preserving uncertainty.

Required remediation:
- unverified contingency/fragility must remain explicitly unknown/unverified rather than being converted to a negative depth assertion;
- use an inspectable `UNKNOWN`/equivalent uncertainty state consistent with existing missing-data honesty;
- do not upgrade unknown evidence into `SCARCE_THIN` or `DANGEROUS`;
- UI reasons/limitations must make the uncertainty understandable.

Required deterministic coverage:
- missing/unverifiable contingency evidence produces an unknown/unverified fragility state, not THIN;
- verified THIN behavior remains unchanged;
- verified COVERED / SCARCE_THIN / DANGEROUS cases remain intact.

### TCW-024-F04 — LOW — dedicated accessibility/mobile loops omit Trade Analyzer

Current evidence gap:
- the new Trade Analyzer has a dedicated desktop browser smoke;
- repository accessibility/mobile audits pass, but their section-navigation loops omit the `trade` route.

Required remediation:
- add Trade Analyzer to the dedicated accessibility audit section loop;
- add Trade Analyzer to the relevant mobile/synced navigation audit coverage where the route is supported;
- preserve private sync-fragment behavior and existing mobile safety checks;
- treat this as missing direct coverage, not proof that an accessibility defect already exists.

Required validation:
- accessibility audit exercises Trade Analyzer on desktop and representative phone layout;
- mobile audit exercises the Trade Analyzer route at the existing audited phone dimensions without horizontal overflow or sync-fragment regression;
- no regression to the other existing sections.
