- preserve current incoming exclusivity behavior.

UI:
- outgoing choices must exclude any player not uniquely owned by the selected user team;
- stale/tampered Add outgoing attempts must independently fail closed;
- uniquely user-owned players remain available.

Tests:
- selected-user + another-roster duplicate outgoing player rejected by domain;
- absent from outgoing selector;
- tampered/stale add rejected;
- normal outgoing remains supported;
- existing incoming ambiguity/free-agent/mixed-opponent cases remain green;
- 1-for-1, 2-for-1, and 1-for-2 remain green.

## REQUIRED REMEDIATION B — PLAYER INPUT UI POLISH

The current desktop screen uses the generic `.connection-form` grid, which makes Add outgoing stretch across a large left area while Add incoming sits visually far away on the right.

Replace that proposal-entry arrangement with a Trade-Analyzer-specific layout.

Desktop/tablet target:
- trade partner is a clear prerequisite control above the player sides;
- below it, show two balanced side-by-side sections/cards:
  - **SEND — <user team>**
  - **RECEIVE — <selected partner>**
- each side contains its own player selector and a compact Add action immediately beside that selector;
- Add actions must not stretch to fill a large column;
- Send and Receive Add actions should have matched sizing/alignment;
- selected-player chips remain directly under their own side;
- Team objective is a separate control below or above the two-side player grid, not interleaved between Add buttons;
- Analyze / Reset remain clear and unchanged in semantics.

Mobile:
- Send and Receive sections stack vertically;
- selector + compact Add remain visually associated;
- no horizontal overflow, clipped labels, or giant full-row Add buttons;
- touch target and accessible-name requirements remain satisfied.

Implementation guidance:
- use Trade Analyzer-specific classes rather than changing global `.connection-form` behavior;
- styling may be added to `src/styles.css`;
- visible button text may be compact (for example `Add`) while preserving explicit accessible names such as `Add outgoing` and `Add incoming`.
