## REQUIRED IMPLEMENTATION

### 1. Package-value source contract

Create or extend a bounded internal contract for an additive asset-value source.

Minimum semantic inputs:
- source ID / version;
- captured/as-of timestamp;
- unit;
- league/scoring/mode metadata;
- explicit Manager-approved/authorized state supplied by trusted application configuration, not user text;
- mapping from ESPN player ID to finite non-negative provider value;
- source freshness/compatibility status;
- per-asset missing/ambiguous/error states.

Production default:
- no approved provider configured.

Do not make a provider "approved" merely because values exist.

### 2. Package-value math

When—and only when—a trusted approved compatible source is present with complete package coverage:
- sum outgoing and incoming source values independently;
- if total value is zero, withhold;
- incomingShare = incoming / (incoming + outgoing);
- outgoingShare = outgoing / total;
- classify on unrounded incoming share:
  - 45% through 55%, inclusive: `FAIR_TRADE`
  - >55%: `YOU_WIN`
  - <45%: `THEY_WIN`
- display may round only after classification;
- 57/43 is relative package asset value, never probability.

Fail closed on:
- no approved source;
- source incompatible with selected league/mode;
- stale source under its configured contract;
- missing/unmapped/ambiguous asset;
- NaN/infinite value;
- unsupported negative value;
- mixed providers/modes/vintages;
- source disagreement where TCW-032 requires generic winner WITHHELD.

Zero is valid only when the approved source explicitly supplies zero; missing never becomes zero.

### 3. Production authority gate

- package-value status WITHHELD;

### 4. Do-nothing and roster consequence

Implement or extend TCW-032's independent user decision:
- `IMPROVES`
- `WORSENS`
- `MIXED`
- `NO_MATERIAL_CHANGE`
- `WITHHELD`

Compare the resolved legal post-trade roster against keeping the current roster.

Preserve explicit follow-up-drop requirements. Never silently drop a player or assume an open-slot free-agent addition.

Package-value winner and roster consequence must remain separate even in test fixtures.

### 5. Starting-lineup impact

Use complete supported pre/post optimized lineups.

Preserve:
- actual configured slots;
- FLEX/OP simultaneous legality;
- current-week locks/actionability;
- full union-roster projection coverage requirements;
- started incoming / benched incoming / displaced / promoted players;
- TCW-032 +/-1.0 point/week UPGRADE/DOWNGRADE/TOSSUP heuristic;
- source/horizon separation.

An incoming high-value asset that stays on the bench must not create fictitious starter gain.

### 6. Depth / fragility / consolidation

Implement the accepted TCW-032 semantics needed by TCW-034:
- contingency coverage before/after;
- newly uncovered configured slots;
- known supported bye gaps where evidence exists;
- 2-for-1 open-slot consequence without automatic waiver points;
- 1-for-2 explicit drop gate;
- consolidation/diversification explanation;
- severe supported gap precedence over positive starter delta;
- SCARCE_THIN / DANGEROUS / UNKNOWN distinctions only where the contract supports them.

Do not manufacture replacement availability or pending season field evidence.

### 7. Replacement / VORP / scarcity

Use only existing approved connected-league structural/available-player and projection evidence.

Preserve:
- full structural pool versus UI shortlist distinction;
- legal slot-aware replacement context;
- FLEX/OP matching;
- conditional replacement scenario separation;
- no double counting of scarcity/VORP into package market value.

When the full/feasible replacement basis is unavailable, WITHHOLD the numeric replacement/scarcity metric while retaining supported structural facts.

### 8. Horizons and confidence

No missing week becomes zero.
