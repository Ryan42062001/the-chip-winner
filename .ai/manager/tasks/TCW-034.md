## REQUIRED IMPLEMENTATION

### 1. Package-value source contract

Create or extend a bounded internal contract for an additive asset-value source.

Minimum semantic inputs:
- source ID / version;
- captured/as-of timestamp;
- unit;
- league/scoring/mode metadata;
- explicit Manager-approved/authorized state supplied by trusted application configuration, not user text;
- mapping from ESPN player ID to finite non-negative provider value;
- source freshness/compatibility status;
- per-asset missing/ambiguous/error states.

Production default:
- no approved provider configured.

Do not make a provider "approved" merely because values exist.

### 2. Package-value math

When—and only when—a trusted approved compatible source is present with complete package coverage:
- sum outgoing and incoming source values independently;
- if total value is zero, withhold;
- incomingShare = incoming / (incoming + outgoing);
- outgoingShare = outgoing / total;
- classify on unrounded incoming share:
  - 45% through 55%, inclusive: `FAIR_TRADE`
  - >55%: `YOU_WIN`
  - <45%: `THEY_WIN`
- display may round only after classification;
- 57/43 is relative package asset value, never probability.

Fail closed on:
- no approved source;
- source incompatible with selected league/mode;
- stale source under its configured contract;
- missing/unmapped/ambiguous asset;
- NaN/infinite value;
- unsupported negative value;
- mixed providers/modes/vintages;
- source disagreement where TCW-032 requires generic winner WITHHELD.

Zero is valid only when the approved source explicitly supplies zero; missing never becomes zero.

### 3. Production authority gate

- package-value status WITHHELD;

### 5. Starting-lineup impact
